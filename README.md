# Cosmos

The Solar System and everything past it in 3D. Planets, moons, comets and spacecraft are where they really were or will be on each date from 1900 to 2100, and you can zoom out past the Oort cloud, the nearby stars, the Milky Way and millions of galaxies to the microwave background at the edge of the observable universe. The app is Thai first (as เอกภพ), with an English version.

```
npm install
npm run dev               # http://localhost:5173
npm run build             # type check, lint and data check, then build to dist/
npm run validate          # check the data files only
npm run fetch-data        # download everything in public/data and public/textures again
npm run check-ephemeris   # compare positions with JPL Horizons on a few dates
```

`npm run fetch-data -- moons spacecraft` runs only those steps. The steps are smallBodies, named, moons, planets, spacecraft, stars and textures. Everything comes from public APIs and takes a few minutes.

Keys: space plays, `+` and `-` zoom, the arrows turn the camera, `[` and `]` jump to the previous or next event, `f` flies to the selected body, `c` makes it (or a nebula, cluster or galaxy, or what an event is about) the center, turning to it from where the camera is, `v` turns the camera to face where the center body is heading, Esc closes the card, Cmd/Ctrl+F searches. The button next to the search opens everything by category: planets, moons by planet, small bodies, spacecraft, regions, clusters, nebulae, galaxies and events (`src/browse.ts`).

## Code style

Formatting and lint come from [Biome](https://biomejs.dev/) (`biome.json`): 2 spaces, single quotes, semicolons, trailing commas, 110 columns, plus a few rules on top of the recommended set (block statements, no `forEach`, no `any`, naming). `npm run format` fixes what it can, `npm run lint` only reports. `npm run check` runs it together with `tsc` and the data check, and pull requests run the same in CI. For VS Code, install the Biome extension; `.vscode/settings.json` formats on save.

## Where positions come from

Everything is heliocentric, ecliptic J2000, in AU.

- Earth, Mercury, Venus, Mars and the Moon come from [astronomy-engine](https://github.com/cosinekitty/astronomy) (VSOP87 and its lunar theory), within about 500 km of JPL for Earth. So do the Galilean moons and every spin axis.
- Jupiter to Pluto follow JPL Horizons paths of each system's barycenter, because astronomy-engine's shortened VSOP87 puts Neptune a few hundred thousand km off. Pluto is moved off its barycenter by Charon's pull.
- Other moons use osculating elements from Horizons, sampled about twelve times per orbit and interpolated.
- Named asteroids, comets, dwarf planets and interstellar objects follow Horizons state vectors, sampled more finely around perihelion. Outside the span Horizons covers they fall back to a two-body orbit, and their card says so.
- Spacecraft follow Horizons too, with 10-minute samples around each planet flyby. Those windows are taken relative to the planet, since a spacecraft's trajectory file carries the planet ephemeris of its day (Neptune in 1989 was some 5,000 km off today's). Past the end of JPL's data, which is 2050 for most of them, the fetch script carries each craft on under the Sun's gravity and the card marks it as coasting.
- JWST is a Horizons path too, taken relative to Earth and shown until it runs out in November 2031. Its orbit line is turned with the Earth–Sun line so the halo round L2 shows as a loop rather than a smear along Earth's year. L2 itself is marked 0.01 AU beyond Earth on the line from the Sun, which is drawn dashed, and the first month's trip out, before it entered the loop on 24 January 2022, is dashed too.
- The ISS and Hubble use one set of mean elements each (CelesTrak, November 2026), with the node and phase drifting as Earth's oblateness makes them. The plane and height are right; where along the orbit they are is not, since reboosts and drag push them off a few degrees within days. Their cards say this. Each is shown from launch to its planned or expected end (`end` in bodies.yaml).
- The asteroid belt, NEOs, Jupiter trojans, centaurs, TNOs and comets are about 61,000 objects from the JPL Small-Body Database, each moved along its own Kepler orbit in the vertex shader. Their elements are fixed at one epoch, so they drift from reality over decades. That doesn't matter as a crowd, but don't read single dots as real positions. The belt cards and the layer's tooltip say this in the app too.

`npm run check-ephemeris` prints the error against Horizons for a set of bodies. In 2026 everything shown is within about 1,200 km, most within a few hundred.

The Oort cloud has never been observed. It is drawn from a model: an inner, flattened Hills cloud from 2,000 to 20,000 AU and a round outer cloud to 100,000 AU, with density falling as r^-3.5. Its card says it is a model. The heliosphere is drawn as two plain shells at the termination shock (94 AU) and heliopause (121 AU), where the Voyagers crossed them.

Comet tails are a model too. Their directions follow the physics: the ion tail points straight away from the Sun and the dust tail curves back along the orbit. Their lengths come from `tail` in `bodies.yaml`, roughly what each comet showed near perihelion, scaled by the inverse square of the distance to the Sun, and they fade out beyond `onset` AU (4 by default). The coma is a soft glow sized from `coma` (km) the same way. The cards say so. 3I/ATLAS's nucleus has never been resolved, so it's drawn as a generic lumpy comet nucleus at the middle of the size estimates (`shape.guess`), and its card says that too.

Every body gets a marker dot a few pixels wide so you can find it from far away. The "True size" layer turns that off: spheres are drawn only at their real size, and anything smaller than a pixel becomes a single faint point. The Sun's glare shrinks the same way, and the small-body and Oort cloud dots fade to a faint trace. Normally those dots are hundreds of thousands of times bigger than the objects, which is why the belts look so crowded; the region cards explain this.

Stars come from the [HYG database](https://github.com/astronexus/HYG-Database) (CC BY-SA 4.0). The 108,000 or so with a parallax distance within 3,000 light years are placed in 3D (`field.bin`), and the shader works out each one's magnitude from wherever the camera is, so from inside the Solar System they make up the night sky and further out they spread into the real neighbourhood. Out there the stars are brightened like a long exposure, or almost none would show. The catalogue is only complete for stars bright enough to measure from Earth, so the field looks thicker around the Sun than it is; the star-field card says so. The few hundred naked-eye stars without a usable distance stay on a sky sphere at infinity and fade out once the camera leaves the Sun. Clusters and nebulae are entries in `regions.yaml` with `at` (RA, Dec, light years); the nebula glows are simple stand-ins.

Nobody has seen the Milky Way from outside, so it's a model built from points (`src/scene/galaxy.ts`), drawn the same way as Andromeda and Triangulum: a bar, an exponential disk and five spiral arms. The parts that are measured are its size, the Sun's distance from the centre (8.18 kpc, GRAVITY 2019) and height above the plane, the tilt of the plane on our sky (the IAU galactic frame), and the arms on our side, which follow the log-spiral fits to maser parallaxes in Reid et al. 2014. The far side, hidden by dust, is the same spirals carried on. The Galaxy's card says all this. Sgr A* and the Magellanic Clouds are placed at their real positions and distances.

The timeline only shows where it means something: on the Solar System out to the Oort cloud, and on the Galaxy and beyond. Close on a nebula or a star there is nothing it can run, so it goes away and anything playing stops. Past 6,000 light years out, days stand still, so the timeline switches to ±250 million years (`deep` in `src/store.ts`) while the Solar System keeps its date. The Sun goes round at the circular speed (233 km/s) and bobs through the plane every 70 million years or so; the spiral pattern, painting and points together, turns as a whole at 20 km/s/kpc, a pattern speed still argued over. The stars themselves go round at the speed of a near-flat rotation curve, so the inner disk laps the arms and the outer disk falls behind them. Blue stars and glowing gas are born in the arms and drift off as they age, fading within 40 and 10 million years, which is why the arms keep their shape while the stars in them move on. The bar stays with the pattern. The scene stays centred on the Sun, so the Galaxy and everything fixed to it move past it instead. Zooming back in turns the Galaxy back to the present.

Further out is the Local Group (`src/scene/localgroup.ts`). Andromeda and Triangulum are point models like the Milky Way, at their measured distances and tilted on our sky by their measured position angle and inclination, so a fly-to along our line of sight shows them as photographed; their arms are only sketched. The dwarf galaxies are soft blobs their measured half-light size, 170 confirmed ones within 3 Mpc from the Local Volume Database (Pace et al. 2024; `npm run fetch-data localGroup` pulls a pinned release). On the million-year timeline Andromeda and its satellites fall toward the Milky Way at the measured 109 km/s, and both spirals turn their patterns whole, at 70% of their measured orbital speeds since their pattern speeds are unknown. Far off, each galaxy draws only as many points as its size on screen needs, brightened to keep the total light, or a few hundred thousand points piled onto a few pixels would stall the GPU.

Past that, out to about 35 million light years, are the 754 other galaxies of the Updated Nearby Galaxy Catalog (Karachentsev et al. 2013), in `src/scene/localvolume.ts`. Each is one flat quad drawn as a sketch of its type (elliptical, spiral or irregular) at its measured distance, size and inclination. The catalogue has no position angles, so those come from the PGC (Paturel et al. 2003) matched by position, about 300 of them; the famous ones the PGC misses or gets wrong (M51, M101, M83, IC 342 and a few more) are set by hand from the papers that measured them, and the rest, mostly small dwarfs, get an arbitrary one. `npm run fetch-data localVolume` rebuilds the file.

Furthest out are the 55,000 galaxies with measured distances in Cosmicflows-4 (Tully et al. 2023), as points out to about 2.6 billion light years (`src/scene/cosmicflows.ts`, `npm run fetch-data cosmicflows`). One galaxy's distance is off by 20% or so, which would stretch every cluster into a streak pointing at us, so all members of a group sit at the group's error-weighted mean. The empty band across the sky is the zone of avoidance, where the Milky Way's own dust hides what lies behind it. A few big clusters are named.

Cosmicflows-4 is patchy on the sky, so the 2MASS Redshift Survey (Huchra et al. 2012) fills it in: some 31,000 more galaxies, complete to K = 11.75 over almost the whole sky, out to about a billion light years (`npm run fetch-data redshifts`). They have only a redshift, so they sit at their velocity over H0 = 75, the scale Cosmicflows-4 is on, and at their group's mean velocity from Tully's (2015) group catalogue so clusters don't stretch into fingers pointing at us.

The 6dF Galaxy Survey (Jones et al. 2009) fills in the southern sky that SDSS missed: its reliable redshifts, about 99,000 not already drawn, placed by redshift in the CMB frame and drawn with the 2MRS ones (`npm run fetch-data sixdf`). I found no group catalogue for it on VizieR, so its clusters keep their fingers of god.

Beyond those are the 2.4 million galaxies of SDSS DR17 with good redshifts, out to z = 0.8, at their comoving distance on the same scale (`src/scene/survey.ts`, `npm run fetch-data sdss`, a few minutes against SkyServer). Below z = 0.2 they take the group-corrected distances of Tempel et al. (2017). The survey covered about a third of the sky, so this part of the map is two fans. The data is about 15 MB, so it is shuffled once and cut into files: the first 100,000 load after the page is up, the rest only once the camera is 100 million light years out, and none of the rest when the browser asks to save data. Any prefix of the shuffled order is an even sample, so the picture fills in evenly as files arrive and a slow machine just draws fewer. All the galaxy points add up unclamped in a half-float target and are toned onto the frame logarithmically, or the dense middle would burn out to white. The exposure goes up as the camera zooms in among them, where they spread out to a few per pixel.

Past SDSS are DESI DR1's luminous red galaxies, star-forming galaxies and quasars from its large-scale structure catalogues, those beyond z = 0.6 only, a random 2.4 million of their 5.3 million, out to about 20 billion light years (`npm run fetch-data desi`, which streams about 600 MB of FITS). Same files and loading as SDSS; the rest of them start to download once the camera is a billion light years out.

Quaia (Storey-Fisher et al. 2024) adds about 1.2 million quasars from Gaia and unWISE over the whole sky, so the deep map isn't only two fans (`npm run fetch-data quaia`). Its redshifts come from Gaia's low-resolution spectra and are rough; quasars DESI has are left out in favour of DESI's. Loaded the same way, from a billion light years out. SDSS, DESI and Quaia each have a toggle.

Out past 1.5 billion light years the timeline switches to billions of years and runs the expansion back to when the universe was about 400 million years old. The scale factor comes from flat ΛCDM with Planck's H0 = 67.7 and Ωm = 0.31; everything beyond the Local Group (the survey galaxies, the Boötes Void and the CMB sphere) is scaled by it about the Sun, and the galaxies fade below an age of about 3 billion years. Nothing is evolved: it is today's galaxies at earlier sizes.

Around everything is the cosmic microwave background from Planck's 2018 SMICA map, on a sphere at the comoving distance of last scattering for the same cosmology, about 41 billion light years (`npm run fetch-data cmb`, which streams the 2 GB HEALPix map, averages it down to Nside 256 and resamples it to an ecliptic PNG). The texture loads only once the camera is out past 12 billion light years.

The Boötes Void is a region (`void` type) at its published place and size (Kirshner et al. 1981). It does show in this data: a sphere about 100 million light years in radius at its centre holds about a fifth of the galaxies the same sphere does elsewhere at that distance. From far out the galaxies in front of and behind it fill it in, so it reads best from close. Zooming works as the observer growing or shrinking: every galaxy catalogue keeps a galaxy at full brightness out to three times the camera's distance from what it is on, and dims it with the square of the distance beyond (`SEEN` in `src/scene/cosmicflows.ts`). Framing the void shows the galaxies round it; zooming into its middle, where the nearest are about 20 million light years off, ends in a black sky. While the camera is on a void everything is drawn true to size, and nothing inside the Milky Way (the Solar System, nearby stars, nebulae, clusters, Sgr A*) is drawn or labelled.

Up close, Sgr A* (`src/scene/sgra.ts`) is a simulated accretion disk, ray traced in a shader: each pixel's ray is bent as light bends around a non-spinning black hole, so the far side of the disk shows over and under the shadow. The shadow is the real size (about 5.2 Schwarzschild radii, which matches the 51.8 µas ring the EHT measured), the gas moving toward us is brighter and bluer, and the disk is tilted so that from Earth it looks roughly like the EHT image. The real Sgr A* is fed so little gas that it has no bright thin disk like this; the card says it's a film-style simulation. The gas turns at its real orbital speed with the timeline (about 33 minutes round the inner edge), so it stops when paused; at fast playback it fades into an even glow rather than strobing. Eleven S-stars move on their measured orbits (Gillessen et al. 2017, S2 from GRAVITY 2019, S4711 and S4714 from Peißker et al. 2020), turned from sky-plane elements into the ecliptic frame. All of it lives in a group placed at Sgr A*, so the vertices are a few thousand AU at most; at 1.7 billion AU from the Sun, 32-bit floats couldn't hold the ring otherwise. The S-star views look along our line of sight, so the orbits look like the published plots. Flying to the hole itself, or to its shadow, ends instead with the disk nearly edge on, rising to the right, its brighter approaching side on the right, as in the film pictures; that takes turning the picture about the look direction (`roll` in `src/scene/camera.ts`), since the camera otherwise keeps ecliptic north up, and drags are turned to match. The roll eases back to level on the next flight. Around them is a model of the nuclear star cluster: 30,000 of its brighter stars, thickening inward as r^-1.5 out to 2 pc, on circular orbits tilted every way at the speed 4.3 million suns give, plus 120 young blue stars in one clockwise disk tilted as measured (Yelda et al. 2014). Since the timeline is gone this close, the centre gets a play control of its own (`src/holeclock.ts`), from real time to ten years a second. It starts playing at a minute a second from the Solar System's date when the camera arrives, shows only the year from a year a second up, and stops when the camera leaves. Past 2 pc the cluster carries on as one population through the bulge to 1.5 kpc, 130,000 stars thinning as r^-2 and flattening to the Galactic plane, since from inside the Galaxy model's few hundred thousand points leave the sky nearly empty. Its stars are drawn a fixed size, so from further than 2,500 light years each is dimmed as 1/d²: the whole keeps the same surface brightness on the way in, a bright speck in the Galaxy model's bulge that grows and breaks up into stars, without anything fading in or out. Small on screen it draws only as many stars as its size needs, and where the middle piles more than one onto a pixel only a share of them, each brighter, or 310,000 points on a few pixels would stall the GPU. Most of the bulge's light though is a bar, 150,000 more stars in a Gaussian about 1.1 × 0.42 × 0.3 kpc, its near end at positive longitude 27° off our line of sight (after Dwek et al. 1995 and Wegg & Gerhard 2013), drawn brighter than the rest so it reads against the sky from here. Between the camera and every one of these stars is dust: a layer along the Galactic plane thinning as exp(-|z|/100 pc), 1 magnitude per kpc in the plane and cut off 15 kpc from the centre. The path through it has a closed form, since height runs straight along a line, and the stars are dimmed by it and reddened (blue loses 1.3 times what visual does, red 0.75). That gives about 1.5 magnitudes at Baade's Window and 8 straight along the plane to the centre; the real figure there is nearer 30, but at 8 the middle is already black. The dust is broken into clouds by noise looked up about 1 and 3 kpc along the line of sight, so from the Solar System the bulge glows either side of a dark, ragged lane, as in photographs. The clouds are made up, not mapped, and the Galaxy model's own disk is not dimmed by any of it. Views and fly-tos to the Galaxy end above its plane (`tilt` in `views.yaml`), because edge on the whole disk piles into one bright line.

## Textures

Planet maps are from [Solar System Scope](https://www.solarsystemscope.com/textures/) (CC BY 4.0). Pluto uses New Horizons' color mosaic (NASA/JHUAPL/SwRI, public domain). Most of its southern hemisphere was in seasonal darkness during the 2015 flyby and was never photographed; that part is painted a plain color (`unmapped` in `bodies.yaml`) and the card says so. Charon uses New Horizons' grey global map (PIA19866, public domain) the same way; the side facing away from Pluto was only seen from far off, so it's blurry. No real maps exist for Ceres at this resolution or for Eris, Haumea and Makemake at all, so those use Solar System Scope's artist's impressions, set with `illustrated: true` in `bodies.yaml`, and their cards say the surface is simulated.

## Nebulae

Thirty-two nebulae are placed at their measured RA/Dec, distance and size (`regions.yaml`). Their shapes are models, in `src/scene/nebulae.ts`, since we only ever see them from one side: each is built from soft points to look right from Earth. Which way each one faces on the sky is set by eye from north-up photographs, as few have a published position angle, and every card says the shape is a model and the facing approximate. Planetary nebulae are open-ended barrels (the Ring is one seen end on), star-forming regions are gas in clumps within clumps with lanes and pillars of dust, and supernova remnants are threads over a shell.

The colours are those of the light the gas really gives off: red from hydrogen alpha, teal from oxygen III, blue from dust scattering starlight. Which part gets which colour, how bright it is, and the dust lanes and pillars are laid out by hand after photographs, and the cards say so. Dust only takes light away, so the points are drawn with premultiplied alpha, light added in the colour and dust in the alpha, and sorted back to front once a nebula is big on screen. That is what makes the Coalsack a dark hole in the Milky Way from here. Each nebula's brightness is set when it is built, from its points summed onto a grid across the sky, so its brightest part comes out just short of white. A nebula too small to see is held at 8 pixels across so it can be found; with True size on it shrinks and fades instead. They are drawn only once the camera is out among the stars, past about 40,000 AU from the Sun, since closer in the sky is the background picture, and not past 25,000 light years from the camera, far enough out to take in the Galaxy. Small on screen, only a few hundred of its points are drawn, made bigger to cover for the rest, since tens of thousands piled on a few pixels is what slowed the whole machine at galaxy scale. Every nebula can also be shown in the colours of a near-infrared picture. For the Pillars that model is drawn after Webb's picture; for the rest it is worked out from the visible one by rule (dust turns see-through and gold, glowing gas blue), and the card says so. Cards show real pictures too, one in visible light and one in infrared where an openly licensed one exists, from ESA/Hubble, ESA/Webb, ESO and NOIRLab (CC BY 4.0) and NASA (public domain), each with its credit and a link to the original. They are in `public/photos`, cut down to 640 px; the list and credits are in `regions.yaml`. Going to a nebula from the search puts the camera on our line of sight to it, so it is seen the way it is photographed.

## Spacecraft models

The models are from [NASA 3D Resources](https://github.com/nasa/NASA-3D-Resources) (public domain), in `public/models`. Voyager and Pioneer are NASA's GLB files with the Draco compression and PNG fallbacks taken out, so no decoder is needed; both Pioneers share one file and both Voyagers the other. NASA only has New Horizons as 3D-printing parts, so its model is those STLs put together as the printing guide shows (dish on top, RTG out of the apex) and coloured by hand. All three are turned so the high-gain dish faces +z, in metres, and the app keeps the dish on Earth, which is how they flew between encounters. Hubble is NASA's model scaled to its real 13.2 m with the aperture on +z, and its two solar array wings split out into nodes of their own that the app turns about their booms to face the Sun (the hinge point, axis and cell side are in each node's extras), the ISS is scaled up to its 109 m truss and turns its arrays the way the real one does, everything outboard of each alpha joint about the truss and each of the eight wings about its mast, and JWST is NASA's model simplified to a third of its triangles. Hubble points at the pole of its orbit on the side away from the Sun, where Earth never blocks the view, and JWST keeps its sunshield to the Sun, both attitudes they really take, and the ISS flies modules first with the truss to the zenith. All files are meshopt-compressed.

A model loads once its craft is a pixel or two across. Out where the craft are the Sun is far too faint to show them, so the light on them is turned up.

They are drawn after everything else in a scene of their own, in metres with the camera at the origin. The main scene's depth buffer is logarithmic in AU, and in 32-bit floats a craft 45 m away (3e-10 AU) gets the same depth for every part.

Focused on a craft, the scale stops are its own: the whole craft (its `radius` in `bodies.yaml` is how far it reaches, booms and all), the world it is passing when one is close, the craft with the Sun, then the Solar System stops wider than that, all kept on the craft.

## Editing the data

All data lives in `data/` as YAML and is checked against `src/data/schema.ts` on load and by `npm run validate`.

- `bodies.yaml`: every named body. `orbit` says where its position comes from (`engine`, `jupiter`, `moon`, `named`, `craft`); a new `moon`, `named` or `craft` body also needs an entry in `scripts/fetch-data.ts` and a fetch.
- `regions.yaml`: belts, the heliosphere and the Oort cloud, plus star clusters, nebulae and galaxies placed with `at`.
- `views.yaml`: the zoom stops in the scale panel. `tilt` views the Galaxy from that many degrees above its plane, and `also` centres the view halfway between `focus` and a second object. `ladder` groups the stops by what the camera is on: `solar` for anything in the Solar System, a region's id for stops of its own (Sgr A* has them, from the shadow out to the S-stars), and `region` for the one stop that frames any other region under its own name. Stops with no ladder are shared from the Galaxy out; on a deep-sky object they keep it in the centre.
- `events.yaml`: timeline events. `importance: 3` stops playback when that box is ticked, 2 shows a toast. `uncertain` adds a note for dates that are estimates.
- `timeline.yaml`: the date range, the slider's stretch and the starting camera.
- `i18n/en/`: English text keyed by id. Names come from the `en` field. UI text is in `src/i18n/th.ts` and `en.ts`.
